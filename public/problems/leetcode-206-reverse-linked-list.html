206. 反转链表 · 三根指针的接力

真正被改写的只有一件事：每个节点的 next 指向。看清 temp 存档、cur.next 拆桥、prev/cur 推进这四步的顺序为什么不能换。

第 0 步

Java 代码 · 执行位置 双指针 + 存档变量


      


      

        
回答你的问题：这两行到底差在哪

        

          

            
temp = cur.next;

            右边带 “.” —— 这是顺着指针走一格，把“下一个节点是谁”这份信息抄进 temp。它是读取，不改结构，唯一目的是存档：因为下一步马上就要把 cur.next 覆盖掉，不先存就再也找不到后面了。
          

          

            
prev = cur;

            右边没有“.” —— 这是纯粹的变量复制，只让 prev 也指向 cur 所在的那个节点。它完全不碰节点内部，链表结构一点没变，作用是让游标前进。
          

          

            
一句话记住

            带“.”的赋值改结构（链表），不带“.”的赋值改游标（遍历进度）。

            所以整个循环里，真正改变链表的只有 cur.next = prev; 这一行；另外三行都只是搬指针、做记录。
          

        

      


      

        
核心不变量

        
    
          
  • prev：已经完成反转的那段链表的头，同时也是 cur 将要指回去的节点。
    • 
          
  • cur：还没处理的那个节点（本轮主角）。
    • 
          
  • temp：只是为了救下 cur.next 的临时存档，生命周期只有一轮。
    • 
          
  • 顺序被锁死：先读、再写、后搬。先搬则新旧信息全乱，先写则后路丢失。
    • 
          
  • 每个节点只被处理一次 → 时间 O(n)；只开 3 个变量 → 空间 O(1)。
