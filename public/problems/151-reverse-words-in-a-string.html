为什么这样写就能成 核心不变量

        
    
          
  • 两次反转 = 单词顺序颠倒、字母顺序复原。整体反转后 "the sky" 变成 "yks eht"，此时单词的位置反了但字母也反了；再逐词反转一次，字母正回来，位置保持反的 → 正是答案。
    • 
          
  • 去空格的精髓是"看上一个写进去的字符"。c != ' ' || sb.charAt(sb.length()-1) != ' ' 靠短路求值工作：c 不是空格就直接追加；c 是空格时才回头看看 sb 末尾是不是空格 —— 是就说明这是"中间多余的空格"，丢掉。
    • 
          
  • 为什么 sb.charAt(sb.length()-1) 不会越界？因为前面已经把开头的空格全部掐掉，第一个进入 sb 的字符必定不是空格，所以只要走到"c 是空格"这一步，sb 一定非空。
    • 
          
  • 三段代码共用同一套双指针模板：reverseString(sb, start, end) 是"反转闭区间 [start, end]"的通用工具。整体反转传的是 [0, n-1]；单词反转传的是 [start, end-1]。
    • 
          
  • 为什么单词区间是 [start, end-1]？因为 end 停下时指向的是空格（或字符串末尾之后），它本身不属于单词，所以要减 1。
    • 
          
  • end 为什么从 1 开始、又用 end = start + 1？都是为了跳过"每个单词的第一个字符"——它必然不是空格，检查它纯属浪费。这是不改结果、只省一次判断的小优化，也是这段代码最容易看晕的地方。
    • 
          
  • 三个循环边界各不相同：start <= end（闭区间去空格，两端都要处理）、start < end（反转，相遇就停）、end < n（找单词右端，end 允许等于 n 表示"末尾之后"）。
    • 
          
  • 复杂度：三次遍历各 O(n)，每个字符在 setCharAt 层面最多被交换一次；额外空间只有新的 StringBuilder，O(n)。
